# AGENT.md — 機構學微縮工作坊 VR(國中生活動版)

本檔是這個專案唯一的需求來源。請完整閱讀後,依「15. 開發順序」自主執行到完成,不需要向使用者詢問。

---

## 0. 工作方式

1. 開始前先寫 `docs/plan.md`:把本檔拆成詳細、可勾選的步驟清單。
2. 進度隨時寫進 `docs/progress.md`:每完成一項就打勾,並寫下「下一步」。對話中斷後,使用者只會說「繼續 docs/progress.md 的下一項」。
3. 遇到規格衝突或本檔沒寫到的事,自己決定,並把決定和理由記在 `docs/decisions.md`。
4. 衝突時的優先順序:
   1. VR 安全與舒適(不暈、不閃、伸手可及)
   2. 活動可用性(20 人同時使用、穩定、斷網仍可玩)
   3. 教學正確性(數學與機構必須正確,國中版不超出國中範圍)
   4. 視覺品質(第 4 節風格)
   5. 其他
5. 每一步都要驗證(測試、截圖或數值檢查)後才打勾。不能驗證的項目,在 `docs/progress.md` 標註「待實機確認」。
6. 不要把任何金鑰、PIN 碼寫進程式碼或 Git。

## 1. 專案背景

- 使用者:約 20 位國中生,每人一台 Meta Quest 3,活動一個上午(約 2.5 小時),以「玩」為主、順便學機構。
- 老師用筆電或平板開「老師控場頁」,可以讓全班跟著同一個畫面,或讓學生自由探索。
- 學生原地站或坐,不走動。所有互動都在伸手範圍內。
- 主流程四關,桿件和齒輪各一半,另有一個彩蛋關:
  1. 關卡一 雨刷(四連桿,含「結構 → 機構 → 機器」三步開場)
  2. 關卡二 曲柄滑塊(把雨刷的搖桿換成滑塊,變成引擎)
  3. 關卡三 齒輪基礎(主線:減速)
  4. 關卡四 齒輪應用(腳踏車、時鐘、電動工具減速機)
  5. 彩蛋 肘節夾鉗(提早完成的學生才玩)
- 教學主線一句話:**機構把一個動作變成我們想要的動作;齒輪用速度換力氣,或用力氣換速度。**

## 2. 技術棧與硬性限制

- Three.js,用 npm 安裝並鎖定精確版本(例如 `three@0.170.0`,選一個發佈超過 14 天的穩定版)。不從 CDN 載入任何執行時資源,所有東西都打包進專案,活動現場只依賴我們自己的網址。
- 建置工具:Vite,ES modules,`import` 組裝。
- WebXR:`immersive-vr`,參考空間 `local-floor`,選用 `hand-tracking`。同時支援手把與手勢。
- 部署:**單一 Cloudflare Worker**,同時提供靜態網頁(Workers Static Assets,目錄 `dist`)和即時同步(Durable Object,SQLite 型,使用 WebSocket Hibernation API)。免費方案只能用 SQLite 型 Durable Object。
- 進入 VR 後網頁輸入框不能用,所以任何文字輸入都放在進入 VR 前的 2D 頁面。
- WebXR 中不使用後處理(OutlinePass、Bloom 等)。描邊用反向外殼法。
- 中文字:Quest 瀏覽器的中文字型不保證存在。請打包一份 Noto Sans TC(OFL 授權)的子集字型,只含專案用到的字。若無法產生子集,就打包完整字型並在 `docs/decisions.md` 記下檔案大小。
- npm scripts 必須有:
  - `npm run dev`:本機開發(Vite)
  - `npm test`:所有單元測試
  - `npm run build`:輸出到 `dist`
  - `npm run preview:worker`:`wrangler dev`,本機測試 Worker 與 Durable Object
  - `npm run loadtest -- --url <網址> --room <房間碼>`:模擬 20 位學生連線
  - `npm run deploy`:`npm run build && wrangler deploy`

## 4. 全域視覺風格:奶油色日光工作坊

以下是使用者指定的風格,所有關卡共用。

- 三渲二卡通渲染,物件帶細而銳利的深棕色輪廓描邊,明暗分明,柔和斜照的電影級打光。
- 每一關都放在一塊規整的正方形底座上,像一件微縮收藏模型。底座是木框加奶油色桌面。
- 背景色固定為 `#FEFDF5`。
- 機構置中偏後,佔畫面約六成,留白充足。周邊放 4 到 5 件小道具,疏密得當。
- 畫面無彈窗、說明文字區、水印。教學資訊全部用場景內物件表達(銘牌、刻度尺、角度弧)。不要任何閃爍的提示圈。
- 機構細節:圓頭金屬桿件,帶倒角、邊緣高光、細微經年磨損(邊緣微亮、淺刮痕)。桿上打孔,銷釘穿過孔形成旋轉對。機架是深棕木塊,有螺絲孔,邊緣貼 mm 刻度。曲柄下方可有帶鉚釘的圓盤。
- 銷釘:鋼色墊片 + 青銅圓頂螺栓 + 紅色定位點。
- 材質要區分:陽極氧化鋁(桿件)、拋光鋼、青銅、木材、紙張、透明塑膠(量角器)、橡膠。金屬用自製的暖色攝影棚環境貼圖反射(程序產生,PMREM 預先處理一次),高光隨視角移動。
- 光照:淡黃色斜照主光加奶油色環境光,桿件投下長而柔和的影子,明暗過渡自然,不死黑。
- 動態要柔和不雜亂:光束中有緩慢漂浮的微塵,窗光輕微移動。
- 品質原則:每個物件獨立建模、獨立渲染,不簡化細節,倒角平滑、邊緣無鋸齒、無穿模。

### 4.1 VR 適配(優先於上面的描述)

- 第三人稱自由觀景只用在電腦預覽:可拖曳旋轉與縮放,限制俯仰角(約 15° 到 70°)、方位角(約 ±70°)與距離,不會看到背面。
- VR 中鏡頭由頭盔決定,程式**不得移動鏡頭**。進入 VR 時,把底座放在使用者前方約 0.55 m,桌面比眼睛低約 0.45 m。提供「重新定位」:雙手同時握住握把 2 秒,或老師頁按鈕。
- VR 背景是 `#FEFDF5` 的淡奶油色空間,加上柔和的地面、接觸陰影和遠方地平線,不要純白無邊界。
- 窗光移動和微塵在 VR 中幅度要更小,不能讓人覺得空間在晃。
- 底座邊長約 0.8 m,機構的抓取點都在伸手範圍內。

### 4.2 「不合併網格」與效能的解釋

- 每個零件仍是獨立的 Mesh,有自己的描邊。
- 完全相同的重複小件(螺栓、鉚釘、墊片、微塵粒子)可以用 InstancedMesh,這不算簡化。
- 只載入目前關卡的資產,其他關卡從場景圖中移除。
- 目標:電腦 60fps,Quest 3 VR 穩定 72fps。若不達標,依序降低:陰影貼圖解析度、微塵數量、framebuffer 縮放比例。不刪模型細節。

## 6. 介面與互動原則

- 全域控制只有兩個:「播放/暫停」和「進階數學」。電腦預覽時是畫面角落的極簡圖示;VR 中是左手腕上的兩顆實體小按鈕(看手腕才出現,不閃爍)。
- 關卡需要的調整(桿長、齒數、換檔、馬達開關、鎖死螺栓)全部做成**場景內可抓的實體物件**:旋鈕、撥桿、可插拔的齒輪、齒輪托盤。這些不算介面。
- 切換關卡:跟隨模式由老師決定;自由模式下,底座前緣有一排小木牌(關卡銘牌),碰一下就切換。
- 互動方式:
  - 手把:扳機或握把在物件附近按下即抓取;遠處物件可用射線點選。
  - 手勢:拇指與食指捏合即抓取;用指尖輕碰按鈕。
  - 電腦:滑鼠拖曳物件;拖曳空白處旋轉視角;滾輪縮放。
- 拖曳旋轉類零件時,用「角度增量」而不是絕對角度,避免跳動。
- 音量與靜音由老師頁統一控制,學生端沒有額外按鈕。

## 7. 數學的三層呈現

國中範圍提醒:國中九年級只學直角三角形的三角比(sin、cos、tan 當作邊長比),沒有計算機時只用 30°、45°、60°,不教三角函數。所以國中版只用比值、加減乘除和比例。

1. **代號標籤**:機構上的代號(θ、φ、μ、z、r 等)是小銅牌。碰一下翻面,顯示一句白話和即時數值,同時對應的角度弧或線段亮起來。再碰一下翻回。
2. **卷軸(國中版)**:每一關桌上有一個紙卷軸道具。拿起或碰觸就展開成一張紙,浮在機構上方偏側。每頁一個步驟,固定四行格式:
   - 白話:一句話說明
   - 公式:符號寫法
   - 代入:代入**現在**機構上的數字
   - 結果:算出的答案,並在機構上同時標出
   紙上有「上一頁 / 下一頁」的紙角可以翻。老師頁可以讓全員同時打開到同一頁。
3. **藍圖模式(進階數學)**:按「進階數學」後,0.4 秒平順過渡成藍圖風:藍底 `#1B4F8F` 加淡格線,零件變半透明藍、只留白色輪廓,疊上尺寸線、中心線、角度弧與進階公式。關閉後回到溫暖工作坊。

公式在場景中的排版:用自訂的 canvas 排版器繪製(支援分數、上下標、希臘字母),字要大(VR 中 0.6 m 距離時字高至少約 2.5 cm),行距寬鬆,每頁不超過四行。

## 8. 關卡規格

每一關都要有:場景佈局、資產清單、互動、任務、卷軸內容、藍圖內容、聲音震動、老師控場的步驟(stage)。

### 8.1 關卡一 雨刷(四連桿)

教學目標:分辨結構、機構、機器;知道雨刷是曲柄搖桿;能說出「最短加最長 ≤ 另外兩根」時曲柄可以整圈轉。

場景:底座上一片傾斜的擋風玻璃(透明塑膠,帶少許水滴),玻璃下方是四連桿:馬達接曲柄,連桿接搖桿,搖桿延伸出雨刷臂與橡膠刷片。刷片掃過的區域會留下乾淨的扇形(水滴被擦掉的效果)。

道具:游標卡尺、透明量角器、六角螺栓與墊片、鉛筆、一個靜置的小齒輪(暗示後續章節)、一本翻開的空白筆記本。

預設尺寸:請在 `fourBar.js` 中搜尋一組尺寸,條件是:葛氏曲柄搖桿;搖桿擺動角 80° 到 100°;最小傳動角 ≥ 40°。把找到的尺寸和驗證結果寫進 `docs/decisions.md`。

老師控場的三個步驟(stage):
1. **結構**:所有銷釘換成鎖死的六角螺栓。學生推動任何桿件都推不動(輕微震動加「喀」聲)。
2. **機構**:螺栓變回銷釘。學生用手轉曲柄,其他桿跟著動,而且動法固定。
3. **機器**:接上馬達(電線接到底座側邊的小開關),馬達自己轉。

互動:
- 曲柄上的把手可抓取轉動;馬達開關是一個撥桿。
- 連桿長度和搖桿長度各有一個實體旋鈕,每格 1 cm(模型尺寸),畫面上的桿件實際變長變短。
- 尺寸不合時(非葛氏),曲柄轉到某個角度就卡住,再推會震動。

任務:
- 「刷乾淨」:調整桿長,讓雨刷的擺動範圍蓋住玻璃上標記的目標區(覆蓋率 ≥ 90%),並轉完一整圈。
- 「整圈不卡」:接上馬達,連續轉三圈都不卡住。
- 加分「找出雙搖桿」:調出一組讓曲柄只能擺動、但連桿能整圈轉的尺寸。

卷軸(國中版):
1. 結構、機構、機器各是什麼(白話,不需公式)。
2. 葛氏判斷:最短 + 最長 ≤ 另外兩根相加。代入四根桿的目前長度,算出結果和機構名稱。
3. 擺動角度:用量角器道具讀出雨刷的擺動範圍。

藍圖:a、b、c、d 尺寸線,水平中心線,角度弧 θ,向量封閉式 r₁ + r₄ = r₂ + r₃(向量),φ、ψ,傳動角 μ 與公式,Grashof 判斷式,極限位置 θ₄₁、θ₄₂。

### 8.2 關卡二 曲柄滑塊(引擎)

教學目標:知道把搖桿換成滑塊就變成曲柄滑塊;行程等於曲柄長的兩倍;認識死點。

過場:從雨刷關卡進入時,播放約 3 秒的動畫:搖桿越變越長,端點畫出的圓弧越來越平,最後換成直線導軌上的滑塊。這對應教科書的「搖桿長度趨近無限大,圓弧導槽變成直線導槽」。

場景:曲柄、小飛輪、連桿、透明汽缸內的活塞(滑塊)。汽缸旁有 mm 刻度尺。

道具:游標卡尺(可抓起來量行程)、六角螺栓與墊片、鉛筆、筆記本、一小罐機油。

互動:抓曲柄把手轉動;播放時等速轉動。

任務:
- 「引擎啟動」:轉一整圈,活塞完成一次來回。
- 「找到死點」:把曲柄停在 0° 或 180° 附近(±4°)1 秒。此時手把震動最強。
- 「量行程」:用游標卡尺量出活塞的移動距離,誤差 2 mm 內就完成,並顯示「行程 = 曲柄長 × 2」。

卷軸(國中版):
1. 行程 = 2 × 曲柄長,代入目前數字。
2. 在 θ = 90° 時,曲柄、連桿和導軌形成一個直角三角形:連桿歪的程度看「對邊 ÷ 斜邊 = 曲柄長 ÷ 連桿長」,代入數字(例如 15 ÷ 50 = 0.3)。
3. 死點:曲柄和連桿排成一直線時,推活塞也轉不動曲柄。

藍圖:x(θ) 公式、φ、傳動角;偏位滑件曲柄的行程公式 s = √((r₃+r₂)² − e²) − √((r₃−r₂)² − e²) 與最小、最大傳動角公式(偏位 e 預設為 0,藍圖中可用旋鈕調整)。

### 8.3 彩蛋 肘節夾鉗

只在自由模式出現,入口是底座角落的一把小夾鉗模型。

場景:手柄(銅橘)、連桿(黃)、夾臂(綠)、底座與支架(深棕),夾臂下方是一塊橡膠塊(灰綠以外的低飽和色,不能用輸出件的綠)。

行為:壓下握把時,連桿逐漸拉直,橡膠塊被壓扁;越過中心點會「喀」一聲鎖死,放手不會彈開;沒越過中心點放手會彈開。

任務:「夾緊並鎖死」、「發現沒過中心點會彈開」。

卷軸(國中版):連桿越接近一直線,夾緊力放大越多。藍圖:β、簡化估算 夾緊力 ≈ 手的力 ÷ (2 × tan β),以及含握把槓桿的實際倍率。

### 8.4 關卡三 齒輪基礎(主線:減速)

教學目標:接觸點走過的弧長一樣,所以轉的角度和半徑成反比;力矩 = 力 × 半徑;轉速和力矩互相取捨。

場景:兩個咬合的齒輪架在木座上。小齒輪(銅橘)由一個小馬達帶動,大齒輪(綠)的軸上有一個捲線滑輪,吊著一個重物。旁邊有一個可替換的齒輪托盤(10、15、20、30、40 齒)。

老師控場的步驟(stage):
1. **問題**:馬達直接連重物(不經齒輪),轉不動,馬達發出吃力的聲音並震動。
2. **弧長**:換成齒輪後,接觸點兩側各畫出一段等長的彩色弧線,同步延伸。大輪的角度扇形小,小輪的大。學生拖動小齒輪,觀察大齒輪轉幾圈。
3. **力矩**:在接觸點畫出兩個等長的力箭頭(大小相同、方向相反),以及兩輪各自的半徑線(力臂)。力臂長的輪子力矩大。重物被拉起來了。
4. **取捨**:學生從托盤換齒輪,底座側面有兩根實體長條刻度(轉速、力矩),一根升高另一根就降低。

互動:抓小齒輪的把手轉動;從托盤拿齒輪替換(放到軸附近會自動吸附,中心距自動調整)。

任務:
- 「舉起重物」:換一組齒輪,讓馬達能把重物拉到頂。
- 「最快的風扇」:把重物換成小風扇,讓風扇轉最快。
- 「A 轉 1 圈,B 轉 2 圈」。

控場小示範(不在主流程,老師按了才出現):
- 無齒摩擦輪:重物一重就打滑。
- 惰輪:加一個齒輪,轉向改變、快慢不變。

卷軸(國中版):
1. 走過一樣長:r_A × θ_A = r_B × θ_B,代入目前半徑與角度。
2. 換成齒數(齒距相同,齒數和半徑成正比):z_A × θ_A = z_B × θ_B。
3. 力矩:τ = F × r,兩輪接觸點的力一樣,所以 τ_B ÷ τ_A = z_B ÷ z_A。
4. 取捨:轉速 × 力矩 兩邊相等(不計損失)。例:10 齒帶 30 齒,轉速變 1/3,力矩變 3 倍。

藍圖:模數 m、節圓直徑 d = m × z、中心距 a = m(z_A + z_B) ÷ 2、角速度比、τω 相等、接觸點速度 v = rω。

### 8.5 關卡四 齒輪應用(腳踏車、時鐘、減速機)

教學目標:三個例子都是「用齒數比換速度和力」;多級減速的總比是各級相乘。

同一個底座上有三個小站,依序由老師切換(stage),自由模式下可碰銘牌切換。

**站一 腳踏車**
- 場景:簡化的腳踏車傳動(踏板曲柄、前齒盤 34/50 齒、鍊條、後齒輪 14/21/28 齒、後輪),架在可調斜度的小坡道上。
- 互動:轉踏板;用兩個撥桿(前變速、後變速)換檔;坡道有平路與爬坡兩種。
- 任務:「爬上坡」(在爬坡模式選到足夠低的檔位,踏板才轉得動);「平路衝刺」(在平路選到踏一圈前進最遠的檔位)。
- 卷軸:齒數比 = 前齒盤 ÷ 後齒輪;踏一圈後輪轉幾圈;踏一圈前進距離 = 後輪轉的圈數 × 輪子周長。代入目前檔位。
- 補充:鍊條讓前後齒輪同方向轉,不需要惰輪。

**站二 時鐘**
- 場景:打開背蓋的時鐘,可以看到兩級複合齒輪:分針軸上的 15 齒小齒輪帶 45 齒;45 齒和 12 齒裝在同一根軸上;12 齒帶 48 齒時針輪。時針輪和分針軸同心,兩根指針同軸。
- 互動:一個齒輪托盤,裡面有五組「齒數相加都是 60」的齒輪對:(30,30)、(20,40)、(15,45)、(12,48)、(10,50)。學生選兩組放到兩級位置。
- 任務:「讓時鐘走對」:分針轉 12 圈,時針轉 1 圈(答案是 3 × 4 或 4 × 3)。
- 為什麼每組相加都是 60:兩級的中心距必須相等,指針才能同軸(這點放在藍圖)。
- 背隙:在這一站帶一句,鐘錶這類精密機構的齒輪間隙很小;藍圖中可以用旋鈕放大背隙,看反轉時指針先晃一下。
- 卷軸:總減速比 = 第一級比 × 第二級比,代入學生選的齒輪。

**站三 減速機(電動螺絲起子)**
- 場景:剖開的電動螺絲起子,馬達小齒輪經兩級減速帶動輸出軸,前端的螺絲慢慢被鎖進木塊。
- 互動:按下開關播放;旁邊兩根實體長條顯示馬達轉速和輸出力矩。
- 任務:「鎖進螺絲」(看完一次動畫即完成,這站以老師講解為主)。
- 卷軸:馬達很快但沒力,經過減速,變慢但有力。

## 9. 任務與徽章

- 徽章是黃銅圓章,掛在底座角落的小木板上(徽章牆)。完成任務時有蓋章動畫、鈴聲和輕震動。
- 徽章名稱寫成「學會了什麼」,不要寫「第幾關完成」。例如:
  - 雨刷:「雨刷工程師:知道雨刷是曲柄搖桿」、「葛氏偵探:會判斷曲柄能不能轉整圈」
  - 曲柄滑塊:「引擎點火:知道搖桿換成滑塊會變引擎」、「死點獵人:找到推不動的位置」
  - 肘節:「鎖緊大師:知道過了中心點就會鎖住」
  - 齒輪基礎:「大力士:知道減速可以增加力矩」、「速度與力氣:知道兩者要取捨」
  - 齒輪應用:「換檔高手:知道爬坡用低速檔」、「鐘錶匠:會用兩級齒輪做出 12 倍減速」
- 沒有排名、沒有計時。
- 任務偵測寫在 `src/teach/missions.js`,條件用運動學模組的數值判斷,不靠動畫。
- 完成狀態同步到老師頁。

## 10. 聲音與震動

- 全部用 Web Audio 合成,沒有外部音檔。第一次使用者點擊或進入 VR 時建立 AudioContext。
- 音效:按鈕、抓取、齒輪每過一齒的輕「喀」、死點的低沉悶響、鎖死的「喀」、卡住的敲擊聲、馬達運轉聲(轉速越高音高越高、吃力時變低)、蓋章鈴聲。音量柔和,不刺耳。
- 手把震動(手勢模式沒有震動硬體,只靠聲音和畫面):抓取、碰到按鈕、齒輪過齒(很輕)、死點(強)、鎖死(強而短)、卡住(中)、蓋章(輕)。
- 同一個震動至少間隔 25 ms,避免連續觸發。

## 11. 老師控場與同步

### 11.1 架構

- 一個房間 = 一個 Durable Object(`idFromName(房間碼)`)。
- 學生頁與老師頁都連 `wss://<同網域>/ws?room=<房間碼>&role=student|teacher`。
- 使用 WebSocket Hibernation API(`ctx.acceptWebSocket`),降低閒置成本。
- 房間狀態與名冊存在 Durable Object 的 SQLite 儲存;最後一次活動 24 小時後用 alarm 自動刪除全部資料。
- 老師身分:連線時送出 PIN,與 Worker 的祕密變數 `TEACHER_PIN` 比對。PIN 錯誤就拒絕並關閉連線。
- 訊息量:學生只在事件發生時送訊息(完成任務、切換關卡或步驟),外加每 15 秒一次心跳。老師只在操作時送訊息。

### 11.2 訊息格式(`src/net/protocol.js`,Worker 與前端共用)

所有訊息都是 JSON,帶 `t`(類型)與 `v`(協定版本)。

- 學生 → 伺服器:`hello {clientId, name}`、`progress {level, stage, badges[]}`、`ping`
- 老師 → 伺服器:`hello {pin}`、`cmd {mode: "free"|"follow"|"pause", level, stage, scroll: {open, page}, blueprint, volume, muted}`、`rename {clientId, name}`、`recenter {clientId|"all"}`、`clear`、`export`
- 伺服器 → 學生:`state {mode, level, stage, scroll, blueprint, volume, muted, seq}`
- 伺服器 → 老師:`state`、`roster [{clientId, name, level, stage, badges, online, lastSeen}]`、`export {csv}`
- 名字:去除 HTML,最長 12 字。單一訊息最大 4 KB,每個連線每秒最多 10 則。

### 11.3 學生端行為

- 自由模式:學生可以自由切換關卡和操作。
- 跟隨模式:關卡與步驟由老師決定,學生仍可操作機構,但不能切換關卡。
- 暫停模式:機構停止,底座前方升起一塊小木牌「請看老師」(這是場景內物件,不是彈窗),畫面不閃爍。
- 卷軸與藍圖:老師開啟時,全員同步開啟到同一頁。
- 斷線:自動進入單機模式,學生照樣能玩;以遞增間隔自動重連(1 s、2 s、4 s,最多 15 s),重連後補送目前進度。

### 11.4 老師頁(`teacher.html`,DOM 介面)

- 輸入房間碼與 PIN 登入。
- 大按鈕:自由 / 跟隨 / 暫停;關卡與步驟選擇;全員打開卷軸並選頁;全員開關藍圖;音量與靜音;全員重新定位。
- 名冊表格:名字、所在關卡、徽章、在線狀態;名字可直接點擊修改。
- 徽章牆檢視(適合投影)。
- 匯出 CSV、清除資料(需要再按一次確認)。
- 版面要適合筆電與平板,字要大,操作不超過兩次點擊。

### 11.5 學生起始頁(`index.html`,DOM 介面)

- 輸入名字(必填)和房間碼(可從網址 `?room=` 帶入),按「進入 VR」。
- 不支援 WebXR 時顯示「用滑鼠預覽」,仍可完整操作。
- 這一頁符合 4 節的風格(奶油色背景、深棕文字),但不是 3D 場景,所以允許有文字。

## 13. 測試與驗收

### 13.1 單元測試(`npm test`)

運動學必須用教科書例題驗證:

- 四連桿 Grashof(例 04-01):r₂ = 12、r₃ = 18、r₄ = 24。曲柄搖桿時固定桿 r₁ 的範圍是 18 ≤ r₁ ≤ 30;參搖桿時是 6 < r₁ < 18 或 30 < r₁ < 54。
- 偏位滑件曲柄(例 04-02):r₂ = 200、r₃ = 600、e = 50 mm。行程 401.57 mm,μ_min = 65.38°(θ₂ = 270°),μ_max = 104.48°(θ₂ = 90°)。
- 四連桿封閉解:隨機角度下,四根桿的長度約束誤差 < 1e-9。傳動角公式和由座標算出的夾角一致。
- 齒輪:隨機角度下兩齒輪的齒形多邊形不相交(或相交面積小於齒面積的 0.1%);同軸複合齒輪的相位正確;時鐘總比等於 12,兩級中心距相等。
- 腳踏車:各檔位齒數比、踏一圈前進距離。
- 協定:訊息編碼解碼、名字過濾、超量拒絕。
- Durable Object:用 `wrangler dev` 或 Miniflare 測試老師指令廣播、PIN 錯誤拒絕、清除資料。

### 13.2 畫面檢查

- 用 Playwright 對每一關、每個步驟、藍圖模式、卷軸各截一張圖,存到 `docs/screenshots/`,逐張檢查:顏色語言、描邊、陰影、無穿模、無多餘文字、無閃爍提示。
- 如果環境無法執行 Playwright,在 `docs/progress.md` 標註,並列出需要使用者手動檢查的畫面。

### 13.3 效能

- 電腦預覽:每關記錄 FPS 與 draw call 數量(`?debug=1` 時顯示一個小型除錯資訊,正式畫面不顯示)。
- Quest 3:列出每關的 draw call、三角形數與預估負載,寫進 `docs/decisions.md`,並標註「待實機確認」。

### 13.4 同步壓力測試

- `scripts/loadtest.js` 模擬 20 位學生連線、送心跳與隨機徽章,並以老師身分確認名冊人數和廣播延遲。

## 15. 開發順序

0. 寫 `docs/plan.md`(詳細步驟清單)與 `docs/progress.md`。
1. **場景佈局方案**:先輸出 `docs/layout-plan.md`,每一關畫出俯視配置(機構、道具、控制物件、徽章牆、卷軸、關卡銘牌的位置與尺寸),並說明在 VR 中的伸手距離。
2. **運動學模組並驗證**:完成 `src/kinematics/` 與第 13.1 節的測試,全部通過才進下一步。
3. **逐一資產建模**:每個零件、道具、控制物件各自一個檔案,獨立建模。
4. **材質與光影**:toon、描邊、環境貼圖、陰影、微塵、窗光。
5. **互動**:電腦預覽與 VR(手把、手勢、重新定位)。
6. **教學層**:代號標籤、卷軸、藍圖模式、任務與徽章、聲音與震動。
7. **同步**:Worker、Durable Object、協定、老師頁、學生起始頁、單機模式、壓力測試。
8. **效能調校**。
9. **逐項檢查**:第 14 節驗收清單,並完成 `README.md`。
10. 部署:執行 `npm run deploy`。需要使用者在瀏覽器授權 `wrangler login`,以及用 `wrangler secret put TEACHER_PIN` 設定 PIN;這兩步請在 `README.md` 寫清楚並提醒使用者。
